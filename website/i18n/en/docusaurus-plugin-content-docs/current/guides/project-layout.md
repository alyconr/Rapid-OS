# File Structure

Rapid OS keeps most governance state under `.rapid-os/`, while leaving artifacts visible when they should be versioned, inspected, and audited.

## Main structure

```text
project/
├── .rapid-os/
│   ├── config.json
│   ├── project.json
│   ├── setup.json                  # onboarding state; written by rapid setup
│   ├── policy.json
│   ├── capabilities.lock
│   ├── standards/
│   ├── specs/<spec-id>/spec.json and revisions/
│   ├── runs/<run-id>/run.json, contract.json, context.md,
│   │   context-manifest.json, and states/
│   ├── harnesses/
│   ├── evidence/<run-id>/records/ and artifacts/
│   ├── evals/<run-id>/reports/
│   ├── session.json                # active run; local state
│   └── scratch/                    # local porcelain state
├── .claude/skills/ .agents/skills/ .cursor/skills/ .github/prompts/ # shortcuts
├── .claude/settings.json           # Claude Code hooks
├── docs/                           # onboarding project documents
├── SPECS.md, TASKS.md, ACCEPTANCE.md
├── references/
└── harness-specific files
```

Not every file exists at startup; files appear when their module is used.

## Porcelain layer files (shortcuts)

| Path | Written by | Contents |
|---|---|---|
| `.rapid-os/session.json` | `rapid start` writes it; `rapid abort` removes it | Active run, mode, harness, start head, and optional workspace details. Local state; not versioned. `rapid finish` does not remove it, so a second finish detects the completed run. |
| `.rapid-os/scratch/checks/<run-id>/<n>.log` | `rapid check` | Full output of each command. Evidence is recorded under `.rapid-os/evidence/`; this log is supporting material. |
| `.rapid-os/backups/<file>.<timestamp>.bak` | `rapid init`, `rapid setup`, and agent-file regeneration commands | Previous agent-file copies; created only when content changes, keeping the five most recent per file. Do not version them. |
| `.rapid-os/scratch/hooks.json`, `hooks.log` | `rapid hook` | Stop-hook loop guard and hook decision log (rotates to `hooks.log.1`). |
| `.claude/skills/<name>/SKILL.md` | `rapid shortcuts install` | Claude Code shortcuts. |
| `.agents/skills/<name>/SKILL.md` | `rapid shortcuts install` | Codex and Antigravity shortcuts (shared directory). |
| `.cursor/skills/<name>/SKILL.md` | `rapid shortcuts install` | Cursor shortcuts. |
| `.github/prompts/<name>.prompt.md` | `rapid shortcuts install` | VS Code / Copilot prompt files. |
| `.claude/settings.json` | `rapid shortcuts install --hooks`, `rapid init --hooks` | Claude Code `Stop` and `PreToolUse` hooks; merged with existing configuration. |
| `../<repo>-<run-id>` | `rapid start --worktree` | Isolated Git worktree on `rapid/<run-id>`, sibling to the repository; path is stored as `workspace_path` in the session. |

Recommended `.gitignore` entries:

```gitignore
.rapid-os/session.json
.rapid-os/scratch/
.rapid-os/backups/
__pycache__/
*.pyc
.pytest_cache/
```

`rapid init` and `rapid setup finish` append missing lines to an **existing** `.gitignore` (they do not create one). The last three entries keep tool artifacts from looking like project changes; `rapid finish` also ignores them by name even if they are absent from `.gitignore` (see [`file_change`](../cookbooks/evidence-engine.md)).

Version shortcut files and `.claude/settings.json` so the whole team uses the same workflow. `rapid shortcuts remove` deletes only files containing `<!-- generated by rapid shortcuts -->`.

## Legacy context files

`rapid init` may generate `.cursorrules`, `CLAUDE.md`, `.agent/rules/constitution.md`, `INSTRUCTIONS.md`, and `AGENTS.md`. It also maintains standards under `.rapid-os/standards/`.

## Onboarding documents

Four `docs/` documents enter context as sources with visible provenance. See [Project Documents and Provenance](../concepts/project-docs.md).

| Context source | Path | Priority | Type | Tags |
|---|---|---|---|---|
| `doc.brief` | `docs/PRODUCT_BRIEF.md` | high | `product` | `product`, `feature`, `spec` |
| `doc.business` | `docs/BUSINESS_RULES.md` | high | `business` | `business`, `domain`, `product` |
| `doc.data-model` | `docs/DATA_MODEL.md` | medium | `data_model` | `data`, `database`, `backend`, `domain` |
| `doc.architecture` | `docs/ARCHITECTURE.md` | high | `architecture` | `architecture`, `topology`, `backend`, `frontend` |

A `docs/` file counts only if its frontmatter has `rapid-doc: <id>` from this table. Frontmatter is never injected into content. Paths and priorities come from `templates/setup/docs/` banks.

## Immutable artifacts

V3 registries favor append-only state and digest integrity: spec revisions are not edited in place; historical `RunState` snapshots are not overwritten; evidence records use sequential IDs; evaluation reports are added by revision; and evidence artifacts are copied and verified by SHA-256 and size.

## Read-only commands

Examples include `rapid guide`, `scan`, `validate`, `doctor`, `inspect-context`, `context`, `spec list/show`, `policy show`, `run list/show`, `harness list/show/resolve`, `evidence list/show/verify`, and `eval list/show`.

| Class | Porcelain verbs |
|---|---|
| Read-only | `rapid next`, `rapid status`, `rapid shortcuts list` |
| Write state | `rapid start`, `check`, `task`, `attach`, `finish`, `approve`, `abort`, `shortcuts install`, `shortcuts remove` |

`rapid next` and `rapid status` only read the ledger and session. `rapid check` runs the supplied command or configured `test_command` and records evidence; `rapid start --worktree` also creates a worktree. `rapid hook` writes only under `.rapid-os/scratch/`. Behavior can change with flags: `rapid scan` writes only with `--write`, and `rapid eval run` saves a report only with `--write`.

## Commands that write state

Examples include `rapid init`, `rapid scan --write`, `rapid scope`, `rapid spec create/revise/status/export-legacy`, `rapid policy init`, `rapid run create/status/task/gate`, `rapid harness init/lock`, `rapid evidence add`, `rapid eval run --write`, `rapid mcp`, `rapid vision`, and `rapid deploy`. See the [CLI reference](../cli.md) for exact flags and contracts.

## Path protection and backups

Rapid OS validates path containment to prevent traversal and symlink escapes in governed registries. Legacy operations that overwrite certain files use `.bak` backups. Regenerated agent files are backed up under `.rapid-os/backups/`, only if content changes, keeping the five latest per file rather than leaving backups in the project root.

## Catalog stacks

Each topology component has a stack; see [Stacks and Components](../concepts/stacks.md). `rapid init --stack <id>` and `rapid setup set stack <id> [--component <c>]` write the selected `templates/stacks/<component>/<id>.md` to `.rapid-os/standards/tech-stack.md`; its `<id>.json` sidecar declares factors, sources, compatible topologies, and supported services.

| Component | Stacks |
|---|---|
| `backend` | `python-fastapi`, `python-django`, `node-nestjs`, `node-fastify`, `go`, `rust-axum`, `ruby-rails`, `dotnet-aspnetcore`, `java-spring-boot`, `kotlin-spring-boot`, `php-laravel` |
| `frontend` | `react-vite`, `nextjs`, `angular`, `vue-vite`, `nuxt`, `svelte-vite`, `sveltekit`, `astro` |
| `docs` | `docs-modern` (Docusaurus), compatible only with `doc-site` |
| all | `generic` (generated from scanner results) and `custom` (agent-written `tech-stack.md`) |

Legacy IDs (`python-api`, `python-ai`, `nodejs-ai`, `web-modern`, `frontend-creative`) remain accepted; see the [`setup.json` migration guide](./setup-json-migration.md).

`rapid validate` recognizes a stack by markers such as `<!-- rapid-stack: backend=go -->` at the end of each `tech-stack.md` section, or by the heading in an older file (`TECH STACK: PYTHON API`, and others).

Path protection secures Rapid OS artifacts but does not replace operating-system or coding-harness permission controls.
