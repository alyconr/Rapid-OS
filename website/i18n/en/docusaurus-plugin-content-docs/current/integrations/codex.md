# OpenAI Codex / CLI Integration

Technical guide to governing code tasks assisted by command-line models and headless environments with **Rapid OS v3**.

## 1. What it is and how it fits with Rapid OS

OpenAI Codex and its command-line tools support automated code generation and transformation in automated environments and development terminals.

**How they fit together:** Rapid OS is the deterministic governance layer. It defines authorized changes through a specification (`Spec`) and an execution contract (`ExecutionContract`). Codex is the external coding engine that produces patches and runs commands.

## 2. Configure Rapid OS

Rapid OS includes a built-in `codex` profile:

```bash
rapid harness show codex
```

Declared capabilities:
- `context.consume`: `supported`
- `repository.read`: `supported`
- `workspace.current`: `supported`
- `repository.write`, `shell.execute`, `tests.execute`: `unknown` (subject to local environment permissions).

To override these capabilities and declare that your local environment permits running tests and modifying files, initialize a project profile at `.rapid-os/harnesses/codex.json`.

## 3. Configure Codex

1. Configure your execution environment and API keys according to the official OpenAI documentation.
2. Give the tool read and write access to the repository.
3. Configure the local execution sandbox to allow the tool to run `python -m unittest`.

## Main workflow: shortcuts

The recommended way to work with Codex is through Rapid OS shortcuts. The [shortcuts guide](../guides/shortcuts.md) describes all nine shortcuts, their workflow, human approval, and common errors.

### Install

```bash
rapid init --shortcuts                                # while initializing a project
rapid shortcuts install --harness codex               # in an initialized project
```

This generates `.agents/skills/rapid-*/SKILL.md` (the nine shortcuts; see the [Codex skills documentation](https://learn.chatgpt.com/docs/build-skills)). Antigravity uses the same directory, so selecting both writes the shortcuts only once. After updating Rapid OS, run `rapid shortcuts install` again.

### Invoke in Codex CLI and the IDE extension

Codex shortcuts are skills. According to the [official skills documentation](https://learn.chatgpt.com/docs/build-skills), use `/skills` or type `$` to mention a skill in Codex CLI or the IDE extension. The `$` form works across Codex variants:

```text
$rapid-init billing API for small businesses, in Python
$rapid-feature add CSV export to the monthly report
```

| Codex variant | How to invoke a shortcut | What `/` shows |
|---|---|---|
| **Codex CLI** (`codex` in a terminal) | `$rapid-<mode>`, or select it from `/skills` | Codex commands only (`/model`, `/skills`, and others). `/rapid-*` does **not** appear; type `$`. |
| **Codex VS Code extension** | `$rapid-<mode>` or `/skills`; skills also appear when typing `/` in the extension | Codex commands and, in the extension, skills. |

Both variants read the same directories (`.agents/skills/` in the project and `~/.agents/skills/` for a global installation), so they do not need separate installs. If `$` does not show the `rapid-*` skills:

1. Open Codex from the project root (Codex searches for `.agents/skills` from the working directory up to the repository root).
2. Check that they exist: `rapid shortcuts list --harness codex`.
3. Check that `rapid` is on the terminal's `PATH` with `rapid --version`; the skill asks Codex to run it.
4. If you updated Rapid OS or installed shortcuts while Codex was open, restart the Codex session.

`$rapid-approve` does **not** approve anything. It shows pending gates and evidence, then gives you the command to run in your terminal. `rapid approve` requires your interactive terminal and returns `RAPID1310` if an agent launches it. The `AGENTS.md` generated by `rapid init` continues to provide project context.

## Advanced mode (v3 commands)

The v3 commands (`rapid spec`, `rapid run`, `rapid evidence`, `rapid eval`, and others) remain available for CI, debugging, and auditing. The sections below retain the manual workflow.

### 4. Provide the Context Bundle and spec

Rapid OS compiles an optimized context package:
```bash
rapid context --manifest
```

Provide the tool with the active spec (`.rapid-os/specs/<spec-id>/spec.json`), the compiled context manifest (`.rapid-os/context/manifest.json`), and the execution contract (`.rapid-os/runs/<run-id>/contract.json`).

### 5. Follow the execution contract and use external tools

The harness must follow the immutable task list (`T001`, `T002`, ...), the authorized paths (`paths`), and the gates declared in policy.

Before external execution, capture the baseline log as `base.log`, register baseline evidence (see [`evidence_baseline.json`](../tutorials/first-governed-project.md#1-register-baseline-evidence-and-acknowledge-gatebaseline)), acknowledge `gate.baseline`, and start the run:

```bash
python -m unittest discover -s tests -t . > base.log 2>&1
rapid evidence add --run <run-id> --input evidence_baseline.json
rapid run gate <run-id> gate.baseline acknowledged
rapid run status <run-id> active
rapid run task <run-id> T001 in_progress
```

### 6. Record results and evidence

After Codex applies changes and runs tests in the external terminal (see the canonical evidence definitions in the [manual walkthrough](../tutorials/first-governed-project.md#7-evidence-collection)):

1. Ingest changed-file evidence using `evidence_files.json`.
2. Ingest test results and the attached log using `evidence_tests.json`.
3. Ingest workspace evidence (`evidence_workspace.json`) and final review evidence (`evidence_review.json`).
4. Update the run state:

```bash
rapid evidence add --run <run-id> --input evidence_files.json
rapid evidence add --run <run-id> --input evidence_tests.json
rapid evidence add --run <run-id> --input evidence_workspace.json
rapid evidence add --run <run-id> --input evidence_review.json
rapid run gate <run-id> gate.tests acknowledged
rapid run gate <run-id> gate.final-verification acknowledged
rapid run task <run-id> T001 done
rapid run status <run-id> finished
```

### 7. Deterministic evaluation

Evaluate the run:
```bash
rapid eval run --run <run-id> --write --require-pass
```

## Windows: sandbox and Git

**Why this happens:** Codex runs commands in a Windows sandbox. In the default `elevated` mode, commands use dedicated, lower-privilege sandbox users ([Windows sandbox documentation](https://learn.chatgpt.com/docs/windows/windows-sandbox.md)). Git may refuse to read a folder owned by another user (`detected dubious ownership`). The Codex page describes the sandbox but not Git; this connection has been observed in practice. As a result, the harness and your terminal see the same folder with different owners.

**What Rapid OS handles:** All Rapid OS Git commands go through one entry point (`rapid_os/orchestration/git.py`) that adds `-c safe.directory=<project root>` and `-c core.fsmonitor=false`. It trusts only the project root, never `*`, and disables fsmonitor so a foreign repository cannot run programs while being read. Therefore, `rapid setup finish`, `rapid start`, and `rapid finish` work inside the sandbox without prompting. Git 2.38 or later honors command-line `safe.directory`; earlier versions ignore it and Rapid OS treats it as `untrusted` (`RAPID1416`).

**What you need to do:** To run Git yourself in that folder (`git status`, `git commit`, and so on), your user-level Git needs the exception. Rapid OS detects this and reports it as a `person_actions` item in `rapid setup finish`, `rapid setup next --json` (`kind: done`), and `rapid doctor`; the shortcut explains the action:

```bash
git config --global --add safe.directory C:/path/to/your/project
```

Use the project root with `/` separators. This needs no administrator privileges and applies only to your user. Never use `--system` or `*`. Run it in your own terminal; the agent must not do it for you.

**Alternative: `unelevated`.** To run commands as your own user, configure the `unelevated` sandbox in `config.toml`:
```toml
[windows]
sandbox = "unelevated"
```

This reduces isolation. The same documentation describes this as a legacy fallback that uses a restricted token derived from your user instead of the `elevated` sandbox user boundary, has weaker network isolation, and does not support denied read paths. Rapid OS works with either mode.

## 8. Common issues

- **The harness tries to modify paths outside scope:** Evaluation detects discrepancies when evidence does not match the contract paths.
- **Test evidence is missing:** Do not close `gate.tests` without valid `test_result` evidence with `exit_code: 0`.
